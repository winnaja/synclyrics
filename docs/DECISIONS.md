### 2026-10-20 · buffer เสียงเริ่มต้น 30ms (จาก 15ms) + watchdog ตรวจ stream ค้าง
- เพราะ: วัดตอน UI วาดอยู่ callback ของเสียงสะดุดได้ถึง ~28ms (GIL) ซึ่งเกิน buffer 15ms → เสียงสะดุดได้ · เสียงห้ามสะดุดสำคัญกว่า latency (นาฬิกาชดเชย latency อยู่แล้ว เนื้อเพลงไม่เลื่อน) · PROMPT ข้อ 7.4 ว่า 10-20ms จึงเป็นการเบี่ยงที่บันทึกไว้
- เพิ่ม watchdog ใน control thread: callback หยุดเรียก >1.5 วิ → เปิด stream ใหม่เอง + log สถิติเมื่อ starvation/underrun/error เพิ่ม (อาการ "เสียงหายกลางเพลง" ที่ผู้ใช้เจอ ผมจำลองซ้ำบนเครื่องนี้ไม่ได้ในการเล่นเต็มเพลง 3.5 นาที — จึงเพิ่มตัวป้องกัน+log ไว้ไล่ต่อ)

### 2026-10-20 · เนื้อเพลงที่ความยาวต่างจากวิดีโอ: ลดคะแนนแบบนุ่ม ไม่ตัดทิ้งที่ 10 วิ

- ผลกระทบ: เวลาเนื้อเพลงอาจเลื่อนทั้งเพลงจนกว่าเฟส 4 (ตรวจ offset ด้วยเสียงร้อง) — ผู้ใช้ปรับด้วย `[` `]` ได้

### 2026-10-19 · audio engine อยู่ใน process หลัก (ตาม PROMPT) + ป้องกัน GIL
- เพราะ: ทำตาม PROMPT ข้อ 1.1 และง่ายกว่า · งานหนักแยก process แล้ว (AI, ffmpeg) · ตั้ง `sys.setswitchinterval(0.001)` · กติกาให้งาน Python ล้วนในตัวหลักแบ่งชิ้น < 5ms
- ทางหนีที่ออกแบบไว้แล้ว: ย้าย engine ไป process แยก (MediaClock รองรับ shared memory, PCM เป็นไฟล์ memmap, คำสั่งเป็น tuple) — ใช้ถ้าเฟส 5 วัดแล้วยังมี underrun
- ไม่ได้เลือก (ตอนนี้): process แยกตั้งแต่แรก (ซับซ้อนกว่า ทำให้เฟส 1 ช้า)

- เปลี่ยนอุปกรณ์ที่ rate ต่างกัน → ถอดรหัสใหม่ (ยอมรับได้ เพราะเกิดน้อย)
