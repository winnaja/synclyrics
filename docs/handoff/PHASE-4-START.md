# PHASE-4-START.md — ใบสั่งงานเริ่มเฟส 4 (AI ฟังเสียง จัดเวลาเนื้อเพลง + แปลไทย)

เขียนเมื่อ 2026-10-20 ตอนจบรอบ UI ของเฟส 2 · ใช้คู่กับ `docs/handoff/PHASE-2.md` และ "งานที่ยัดไว้ให้เฟสถัดไป" ใน `docs/PROGRESS.md`
**โมเดล/ระดับ:** Sonnet 5.5 · **high** (เปลี่ยนจาก medium) · เริ่มในแชตใหม่

## เป้าหมาย (เรียงตามความสำคัญ — ผู้ใช้สั่งซ้ำ 2 ครั้ง ห้ามหล่น)
1. **จัดเวลาเนื้อเพลงจากเสียงจริงของคลิป** สำหรับ MV/คลิปที่ไม่ใช่ official audio/รีมิกซ์ — ไม่ใช่แค่คัดลอกเนื้อสำเร็จรูปมาวาง · ใช้โมเดลฟรีตัวไหนก็ได้
   - เคสทดสอบหลัก: `kRRrsIUxPpM` (เกี่ยวกันไหม MV — เนื้อจาก QQ Music ยาวต่างวิดีโอ 61 วิ เวลาเลื่อนทั้งเพลง) · `rPzC1o8E4t0` (สลักจิต MV — ต่าง 111 วิ)
   - ผลต้อง **ทยอยเข้า UI** (เริ่มจาก 20–30 วิแรก ไม่รอจนจบ) แบบ smooth ไม่กระโดด
2. **ไฮไลต์ทีละคำให้ตรงคำร้อง** (ตอนนี้เวลาทีละคำเป็นการประมาณจากจำนวนตัวอักษร)
3. **คำแปลไทย "แปลสวย บริบทดี"** — โมเดลแปลคุณภาพดีที่รันในเครื่อง ใช้บริบททั้งเพลง ไม่แปลทีละบรรทัดโดดๆ (UI แสดงใต้บรรทัดมีแล้ว)
4. **คำเน้นแบบ Apple Music:** เติม `emphasis: true` ให้คำที่ลากเสียงยาว/คำสำคัญ — ฝั่ง QML อ่าน `modelData.emphasis` แล้ว (`LyricLine.qml`) เหลือแค่ใส่ใน `Word` + `word_to_dict` (`app/ui/lyrics_model.py`)
5. **ช่วงไม่มีคนร้อง** (อินโทร/โซโล่/เอาท์โทร) — ผู้ใช้ตอบ 2026-10-20 ว่า **จุด 3 จุดเดิมก็โอเค ไม่ต้องเปลี่ยนเป็น ♪** · ให้ AI ทำให้ช่วงแม่นและครอบคลุมก่อนบรรทัดแรก/หลังบรรทัดสุดท้าย (♪ เป็นตัวเลือกเสริมทีหลัง) — เงื่อนไขและแผน UI อยู่ใน `docs/PROGRESS.md` ข้อ "ช่วงไม่มีคนร้อง" · ใช้ `app/ai/pipeline/vocal_activity.py`
6. ตรวจเวอร์ชัน (official/MV/รีมิกซ์/คาราโอเกะ) จากเสียง · ตัดเนื้อเพลงที่ไม่ตรงเวอร์ชัน
7. (ส่งต่อเฟส 7) เก็บข้อมูลที่เฟส 7 ต้องใช้: แหล่งเนื้อ + วิธีจัดเวลา (`WordTimingSource`) ต่อ video_id — ดู DECISIONS ท้ายไฟล์

## ข้อจำกัดสำคัญ
- **แอปไม่เล่นเสียง** → AI ต้องโหลดเสียงของคลิปเองเบื้องหลัง (`YouTubeClient.fetch_and_download` ด้วย yt-dlp เพื่อวิเคราะห์เท่านั้น) · ไฟล์เสียงจาก yt-dlp เป็น opus ~137k ไม่ว่ามี cookies หรือไม่ (Premium audio ใช้ไม่ได้)
- **cookies.txt เป็นความลับ:** ห้ามอ่าน/พิมพ์เนื้อหา/commit/ใส่ในล็อกหรือรายงาน · `extension/key.pem` ห้าม commit
- ห้ามใช้โลโก้/asset ของ Apple/YouTube
- เครื่องผู้ใช้: Windows 11 · RTX 4060 · Python 3.12 `.venv` · torch **ยังไม่ติดตั้ง** (`requirements-ai.txt`: torch 2.11+cu128) · ffmpeg 8.1 · Node 24
- bash tool: เขียนสคริปต์ด้วย Write tool ไม่ใช้ heredoc ที่มี `'`/ภาษาไทย · อย่าฆ่า process ด้วย regex ที่ตรง shell ตัวเอง
- ผู้ใช้คุยภาษาไทย ตอบภาษาไทย · อย่า commit ถ้าไม่ได้สั่ง · กฎเฟส: PROMPT 0.3.1 (ปัญหาเฟสนี้แก้เลย · เฟสถัดไปยัดไว้ใน PROGRESS · เฟสก่อนหน้าทำงานเฟสตัวเองให้เสร็จก่อน)

## แผนที่แนะนำ (ทำเป็นขั้น ตรวจทีละขั้น)
1. ติดตั้ง torch + โมเดล (ถามผู้ใช้ก่อนดาวน์โหลดไฟล์ใหญ่: ระบุชื่อ/ขนาด) · เช็ก GPU (`app/ai/gpu.py`)
2. ดาวน์โหลดเสียงเบื้องหลัง → (ทางเลือก) แยกเสียงร้อง → ถอดเสียง/forced alignment กับเนื้อเพลงที่มี (ตัวเลือก: faster-whisper large-v3, WhisperX/wav2vec2 CTC; เลือกที่วัดผลจริงบนเคสทดสอบ)
3. หา offset/สเกลเวลาของเนื้อทั้งเพลงก่อน (เคส MV ที่เลื่อนทั้งเพลง) แล้วค่อย align ทีละคำ · ส่งผลทยอยเป็นชิ้น 20–30 วิ
4. วัดความตรง: เทียบกับเวลาที่ฟังจริงบน `kRRrsIUxPpM` และ `rPzC1o8E4t0` + เพลง official 2–3 เพลงที่เวลาดีอยู่แล้ว (ต้องไม่แย่ลง)
5. แปลไทยด้วยโมเดลแปลในเครื่อง (ใช้ทั้งเพลงเป็นบริบท) · cache ผลลง SQLite
6. คำเน้น `emphasis` · ตรวจเวอร์ชัน
7. test + อัปเดต ARCHITECTURE/DECISIONS/PROGRESS/handoff PHASE-4.md

## ค้างจากเฟส 2 ที่ต้องรู้ (ยังไม่ปิดเฟส 2 — รอผู้ใช้ทดสอบเอง)
ตรวจเองแล้ว (2026-10-20): 
- **วอลลุ่ม/ปิดเสียง/กรอ/เล่น-หยุด ผ่านกับ Chrome ตัวจริง** (`node tests/e2e/chrome_e2e.js` 19/19: ตั้งเสียงจากแอป → `movie_player.getVolume()`=37, mute/unmute, ผู้ใช้ปรับเสียงใน YouTube → แอปรับค่า) · เพิ่ม command `volume`/`mute` ใน bridge และ `volume/muted` ใน status
- **บรรทัดที่ร้องอยู่อยู่กลางจอ:** วัดด้วยสคริปต์ (ฟังก์ชัน `LyricsView.centerOffset()`) พบว่าเดิมสปริงตามช้า (ใช้เวลา ~1.7 วิกว่าจะถึงกลางเมื่อบรรทัดเปลี่ยนไกล → ผู้ใช้เห็นต่ำกว่ากลาง ~80px) → เพิ่มความเร็วสปริง ตอนนี้ถึงกลางใน ~0.9 วิ
- **จับท่อนเดียวกัน:** ลองกับเนื้อเพลงจริงในแคช — จับเฉพาะประโยคต่อกัน (ไม่ลามทั้งเพลง) ท่อนละ ≤3 บรรทัด
- **สีพื้นหลัง:** ทดสอบทุกปกในแคช เฉดสีตรงกับปก (ปกม่วงได้ม่วง ปกทะเลได้น้ำเงินล้วน) · ผู้ใช้เห็นเองว่าม่วงเป็นของแอปรุ่นเก่า/สีเริ่มต้น (แก้แล้ว)
- **เปิดมาแบบขยายเต็มจอ — ยังไม่ได้ผลจริงบนเครื่องผู้ใช้ (ค้างเล็ก):** `cfg.fw_maximized` ใช้งานได้หลังเปิดแล้ว (fullscreen/ออก/ปิดตัวเลือกถูกต้อง) แต่ตอนเปิดแอปครั้งแรก Qt ตั้งสถานะ Maximized แล้วหน้าต่าง Windows ไม่ขยายจริง (geometry ค้างตามค่า x/y/w/h ที่จำไว้) · วิธีที่ใช้ได้คือ `showNormal()` แล้ว `showMaximized()` ซ้ำ แต่เมื่อใส่ Timer ใน `FullWindow.qml` ทดสอบค้าง (อาจวนจาก visibleChanged/visibilityChanged) จึงถอนออก — ถ้าจะทำ: สั่งซ้ำครั้งเดียวหลังหน้าต่างแสดงแล้ว และทดสอบแบบไม่ให้ค้าง
ยังต้องให้ผู้ใช้ยืนยันบนเครื่อง: เปิดแอปรุ่นใหม่ (ปิดรุ่นเก่าก่อน + รีโหลดส่วนขยาย/รีเฟรชแท็บ) แล้วลองใช้จริง
- หน้าตั้งค่าเป็น 9 หมวด + ค้นหา + "โหมดละเอียด" (มุมขวาบน) — ผู้ใช้เคยบอกว่ายังงง ถ้ามีคำติมาเพิ่มให้แก้คำ/ย้ายตัวเลือกไปโหมดละเอียด
