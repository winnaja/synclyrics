# MASTER SPECIFICATION — YouTube Desktop Lyrics Overlay
## Complete UI/UX, Visual Design, Animation & Lightweight Systems

**Project type:** Desktop Lyrics Display Application  
**Primary platform:** Windows 10 / Windows 11  
**Primary music source:** YouTube  
**Core purpose:** แสดงเนื้อเพลงที่สัมพันธ์กับเพลงที่กำลังเล่นบน YouTube ผ่านหน้าต่างลอยบน Desktop

---

# 1. CORE CONCEPT — แนวคิดหลัก

สร้างแอปแสดงเนื้อเพลงบน Desktop ที่มีความสวยงาม เรียบง่าย ทันสมัย และลื่นไหล โดยนำแนวคิดการออกแบบจาก Apple Music Lyrics, QQ Music Desktop Lyrics และ Floating Lyrics Overlay มาประยุกต์ใช้

แอปนี้ไม่ใช่ Music Player และไม่ใช่ Music Streaming Application

### สิ่งที่แอปต้องทำ
- ตรวจจับเพลงที่กำลังเล่นบน YouTube
- แสดงเนื้อเพลงที่ตรงกับเพลงนั้น
- ซิงก์เนื้อเพลงให้สัมพันธ์กับตำแหน่งการเล่น
- แสดงเนื้อเพลงในหน้าต่างลอยบน Desktop
- ปรับแต่งหน้าตาและเอฟเฟกต์ได้
- ทำให้การอ่านเนื้อเพลงดูเป็นธรรมชาติและไม่รบกวนการใช้งานคอมพิวเตอร์

### สิ่งที่แอปไม่ควรทำ
- ไม่สร้าง Music Player ของตัวเอง
- ไม่สร้างระบบค้นหาเพลงหรือคลังเพลงแบบแอปฟังเพลง
- ไม่สร้าง Playlist หรือระบบจัดการอัลบั้มที่ไม่จำเป็น
- ไม่ใส่ปุ่มควบคุมเพลงจำนวนมาก
- ไม่ออกแบบหน้าตาให้เหมือน Dashboard ที่มีข้อมูลเต็มหน้าจอ
- ไม่ใส่เอฟเฟกต์ทุกอย่างพร้อมกันจนดูรก
- ไม่ทำให้หน้าต่างเนื้อเพลงบดบังวิดีโอหรือการทำงานอื่น

**เป้าหมายสูงสุด:** ผู้ใช้เปิด YouTube แล้วสามารถอ่านเนื้อเพลงบน Desktop ได้อย่างสวยงาม โดยไม่จำเป็นต้องสลับหน้าต่างไปมา

# 2. VISUAL DESIGN SYSTEM — ระบบออกแบบภาพรวม

## 2.1 Design Language

ใช้แนวทางการออกแบบแบบ Modern Minimalism ผสม Premium Desktop Utility

คุณสมบัติหลัก:
- Clean
- Minimal
- Elegant
- Smooth
- Lightweight
- Modern
- Premium
- Unobtrusive
- Consistent

องค์ประกอบทุกอย่างต้องมีเหตุผลในการแสดงผล ไม่เพิ่มองค์ประกอบเพียงเพื่อให้ดูมีลูกเล่น

## 2.2 สีหลัก

กำหนดธีมเริ่มต้นเป็น Dark Glass / Soft Black

สีแนะนำ:

| Element | สี |
|---|---|
| Main text | `#F5F5F7` |
| Secondary text | `#A1A1AA` |
| Inactive lyrics | `#777780` |
| Accent | `#A5B4FC` |
| Glass background | Black with adjustable opacity |
| Border | White with very low opacity |
| Hover | Slightly brighter than the original state |

ไม่จำเป็นต้องใช้สี Accent ตามตัวอย่างตายตัว ควรเปิดให้ผู้ใช้ปรับแต่งได้

### Theme presets
- Pure Black
- Soft Dark
- Frosted Glass
- Minimal Transparent
- Light
- Custom Theme

แต่ละธีมต้องออกแบบให้ตัวอักษรอ่านง่ายทั้งบน Wallpaper สว่างและมืด

## 2.3 Typography

เนื้อเพลงต้องเป็นองค์ประกอบที่โดดเด่นที่สุด

รองรับ:
- Font family
- Font size
- Font weight
- Line spacing
- Letter spacing
- Text alignment
- Text shadow
- Highlight weight
- Translation font size

ควรเลือกฟอนต์ที่อ่านง่ายและรองรับภาษาไทย อังกฤษ เกาหลี ญี่ปุ่น และอักษรพิเศษ

ฟอนต์เริ่มต้นควรเป็น Sans-serif ที่ดูสะอาด ไม่ใช้ฟอนต์ตกแต่งจนอ่านเนื้อเพลงยาก

# 3. MAIN FLOATING LYRICS WINDOW

หน้าต่างเนื้อเพลงลอยเป็นองค์ประกอบหลักของแอป

## 3.1 Frameless Window

หน้าต่างต้องไม่มีกรอบ Window แบบโปรแกรมทั่วไปเมื่ออยู่ในโหมด Floating Lyrics

ลักษณะที่ต้องการ:
- ไม่มี Title Bar แบบ Windows
- ไม่มีขอบหนา
- ไม่มีแถบเมนูถาวร
- พื้นหลังโปร่งใสหรือเป็นกระจกฝ้าได้
- มุมโค้งปรับได้
- เงาบาง ๆ เมื่อเปิดใช้
- ลากย้ายตำแหน่งได้
- ปรับขนาดได้
- จดจำตำแหน่งและขนาดล่าสุด

หน้าต่างต้องไม่ปรากฏใน Taskbar หรือ Alt+Tab โดยไม่จำเป็น หากเทคโนโลยีของแอปรองรับ

## 3.2 Floating Lyrics Layout

รองรับการแสดงผล 3 รูปแบบหลัก

### A. Minimal Mode

แสดงเฉพาะเนื้อเพลงบรรทัดปัจจุบัน

องค์ประกอบ:
- เนื้อเพลงบรรทัดปัจจุบัน
- Translation แบบเลือกเปิดได้
- ไม่มีพื้นหลัง หรือใช้พื้นหลังโปร่งใสมาก
- ไม่มีปุ่มควบคุมแสดงค้างไว้

เหมาะสำหรับผู้ใช้ที่ต้องการความเรียบง่ายสูงสุด

### B. Focus Mode

แสดงเนื้อเพลง 3 บรรทัด

- บรรทัดก่อนหน้า: สีจาง
- บรรทัดปัจจุบัน: เด่นที่สุด
- บรรทัดถัดไป: สีจางกว่าบรรทัดปัจจุบัน

บรรทัดปัจจุบันต้องอยู่ในตำแหน่งที่อ่านได้ง่าย โดยมีระยะห่างที่สมดุล

นี่ควรเป็นรูปแบบเริ่มต้นของแอป

### C. Full Lyrics Mode

แสดงเนื้อเพลงทั้งหมดในหน้าต่างขนาดใหญ่

รองรับ:
- Auto-scroll
- Highlight บรรทัดปัจจุบัน
- แสดงคำแปล
- ปรับขนาดตัวอักษร
- คลิกบรรทัดเพื่อเลื่อนไปยังตำแหน่งเวลาของเพลงได้ หากระบบเชื่อมต่อ YouTube รองรับการ seek อย่างถูกต้อง

การเลื่อนอัตโนมัติต้องหยุดหรือเปลี่ยนพฤติกรรมอย่างเหมาะสมเมื่อผู้ใช้เลื่อนอ่านข้อความด้วยตนเอง

## 3.3 Window Size

ผู้ใช้สามารถ:
- Resize ด้วยการลากขอบ
- เลือกขนาดสำเร็จรูป
- ปรับความกว้างของข้อความ
- กำหนดจำนวนบรรทัดที่แสดง
- กำหนดขนาดตัวอักษร
- Reset ขนาดกลับค่าเริ่มต้น

หน้าต่างต้องไม่บีบตัวอักษรจนอ่านยาก และต้องจัดการข้อความยาวอย่างเหมาะสม

## 3.4 Window Position

รองรับ:
- ลากวางตำแหน่งได้อย่างอิสระ
- Snap to screen edges
- Center horizontally
- Top center
- Bottom center
- Top left / Top right
- Bottom left / Bottom right
- Remember last position

หากตำแหน่งเดิมอยู่นอกพื้นที่หน้าจอหลังเปลี่ยนความละเอียดหรือถอดจอเสริม แอปต้องย้ายหน้าต่างกลับเข้ามาในพื้นที่ที่มองเห็นได้

# 4. LYRICS ANIMATION ENGINE

ส่วนนี้เป็นหัวใจของความรู้สึกพรีเมียม

ทุกแอนิเมชันต้องดูเป็นธรรมชาติ ไม่กระตุก และไม่ทำให้ข้อความอ่านยาก

## 4.1 Smooth Auto-scroll

เมื่อเพลงเปลี่ยนบรรทัด:
- เนื้อเพลงต้องเลื่อนอย่างต่อเนื่อง
- ไม่กระโดดเปลี่ยนตำแหน่งทันที
- ไม่มีการกระพริบของข้อความ
- ไม่เลื่อนเร็วเกินไป
- ไม่เลื่อนซ้ำโดยไม่จำเป็น
- ไม่รีเซ็ตตำแหน่งทุกครั้งที่มีการอัปเดตเวลา

ใช้ easing ที่นุ่มนวล เช่น ease-in-out หรือ spring ที่มีแรงเด้งต่ำ

การเคลื่อนไหวควรดูเหมือนข้อความกำลังลอยขึ้น ไม่ใช่รายการข้อความที่ถูกเปลี่ยนทีละแถว

## 4.2 Lyrics Transition

เมื่อเปลี่ยนบรรทัด ให้รองรับ:
- Fade transition
- Smooth vertical movement
- Fade + movement
- Soft scale transition แบบละเอียดอ่อน

ค่าเริ่มต้นควรใช้ Fade + Smooth vertical movement

หลีกเลี่ยง:
- การเด้งแรง
- การหมุนข้อความ
- การซูมเข้าออกบ่อย ๆ
- การสั่น
- การเปลี่ยนสีฉับพลัน

## 4.3 Current Line Highlight

บรรทัดปัจจุบันต้องเด่นกว่าบรรทัดอื่นอย่างชัดเจน

รองรับรูปแบบ:
- Brightness highlight
- Color highlight
- Weight highlight
- Soft glow
- Progressive karaoke fill

การ Highlight ต้องไม่ทำให้ตัวอักษรเบลอหรือสูญเสียความคมชัด

## 4.4 Word-by-word Karaoke Highlight

หากมีข้อมูล Timestamp ระดับคำ ให้ไฮไลต์ตามคำที่ร้องจริง

ลักษณะ:
- คำที่ร้องไปแล้วเปลี่ยนเป็นสี Highlight
- คำที่กำลังร้องเด่นชัด
- คำที่ยังไม่ร้องมีสีจางกว่า
- การเปลี่ยนผ่านต้องสัมพันธ์กับเวลาเพลง
- รองรับการหยุดเพลงและการกระโดดเวลา
- รองรับการกลับไปฟังซ้ำ

เลือกเอฟเฟกต์ได้:
- Smooth Color Fill
- Word-by-word Highlight
- Soft Glow
- Simple Line Highlight

หากมีเพียง Timestamp ระดับบรรทัด ห้ามอ้างว่าเป็นการซิงก์ระดับคำที่แม่นยำจริง ให้ใช้ Line Highlight หรือระบุว่าการแบ่งเวลาระดับคำเป็นการประมาณ

## 4.5 Animation Performance

- ใช้การอัปเดตภาพอย่างมีประสิทธิภาพ
- ไม่สร้าง Animation ใหม่ทุกครั้งที่เวลาเปลี่ยน
- หลีกเลี่ยงการเรนเดอร์ทั้งหน้าต่างใหม่โดยไม่จำเป็น
- หยุดหรือลดงาน Animation เมื่อหน้าต่างถูกซ่อน
- รองรับการลด Motion สำหรับผู้ใช้ที่ไม่ต้องการแอนิเมชัน

ต้องให้ความสำคัญกับความลื่นไหลและความถูกต้องของข้อความมากกว่าเอฟเฟกต์ที่ซับซ้อน

# 6. YOUTUBE CONNECTION & PLAYBACK SYNCHRONIZATION

ระบบนี้มีไว้เชื่อมต่อข้อมูลกับ YouTube เท่านั้น ไม่ใช่ระบบเล่นเพลง

## 6.1 YouTube Detection

แอปต้องตรวจจับวิดีโอหรือเพลงที่กำลังเล่น และพยายามอ่านข้อมูลที่จำเป็น ได้แก่:
- Video title
- Artist หรือ Channel เมื่อหาได้
- Video ID
- Playback position
- Playing / Paused state
- Video duration เมื่อมีข้อมูล

หากมีหลายแท็บ YouTube เปิดพร้อมกัน ต้องมีวิธีเลือกว่าจะติดตามแท็บใด และไม่สลับเพลงไปมาโดยไม่มีเหตุผล

## 6.2 Connection Architecture

ให้เลือกวิธีเชื่อมต่อที่เหมาะสมกับสถาปัตยกรรมของโปรแกรม เช่น Browser Extension หรือการเชื่อมต่อกับหน้า YouTube ผ่านวิธีที่ได้รับอนุญาต

ห้ามสมมติว่าโปรแกรม Desktop ทั่วไปสามารถอ่านชื่อเพลงและตำแหน่งเวลาจากแท็บ YouTube ได้เองอย่างแม่นยำ โดยไม่ต้องมีระบบเชื่อมต่อ

หากเลือก Browser Extension:
- ใช้ข้อมูลจากแท็บ YouTube ที่ผู้ใช้อนุญาต
- ส่งเฉพาะข้อมูลที่จำเป็นให้แอป
- รองรับการเชื่อมต่อใหม่เมื่อแท็บ Reload
- แจ้งสถานะเมื่อไม่พบแท็บที่รองรับ
- ไม่เก็บข้อมูลการท่องเว็บที่ไม่เกี่ยวข้อง

ต้องตรวจสอบความเป็นไปได้ของเทคโนโลยีที่เลือกก่อนเริ่มพัฒนา

## 6.3 Playback Synchronization

เมื่อวิดีโอเล่น:
- อัปเดตตำแหน่งเวลา
- แสดงเนื้อเพลงตาม Timestamp
- เลื่อน Highlight ตามเพลง

เมื่อวิดีโอหยุด:
- หยุดการเคลื่อนไหวที่อิงเวลาเพลง
- คงเนื้อเพลงในตำแหน่งที่ถูกต้อง

เมื่อผู้ใช้ลากเวลาไปตำแหน่งอื่น:
- คำนวณบรรทัดปัจจุบันใหม่
- อัปเดต Highlight โดยไม่ต้องไล่ผ่านทุกบรรทัด
- ป้องกันการแสดงเนื้อเพลงเก่าค้างบนหน้าจอ

เมื่อเพลงเปลี่ยน:
- ตรวจสอบตัวตนของเพลงใหม่
- โหลดเนื้อเพลงใหม่
- แสดง Loading State อย่างเรียบง่าย
- เปลี่ยนข้อความอย่างนุ่มนวลโดยไม่แสดงเนื้อเพลงจากเพลงก่อนหน้าปะปน

## 6.4 Timing Offset

รองรับการปรับ Offset เพื่อแก้กรณีเนื้อเพลงเร็วหรือช้ากว่าเสียง

- ปรับให้เนื้อเพลงแสดงเร็วขึ้นหรือช้าลง
- มีปุ่ม Reset
- บันทึกค่าที่ตั้งไว้
- แสดงผลการเปลี่ยนแปลงทันที

ต้องใช้ตำแหน่งเวลาเพลงเป็นแหล่งอ้างอิงหลัก ไม่ใช้เวลาจาก Animation เป็นตัวกำหนดตำแหน่งเพลง

# 7. LYRICS DISPLAY FEATURES

## 7.1 Lyrics States

ออกแบบสถานะให้ครบ:
- Connecting
- Searching Lyrics
- Loading Lyrics
- Lyrics Available
- No Lyrics Found
- Unsupported Video
- Connection Lost
- Lyrics Syncing
- Instrumental Section
- Error

ทุกสถานะต้องมีข้อความที่เข้าใจง่ายและไม่แสดง Error Stack หรือข้อมูลทางเทคนิคแก่ผู้ใช้ทั่วไป

## 7.2 Translation

รองรับการแสดงคำแปลหากมีข้อมูล:
- เปิด/ปิด Translation
- แสดงคำแปลใต้บรรทัดต้นฉบับ
- ปรับขนาดและสีของคำแปลแยกจากต้นฉบับ
- เลือกภาษาคำแปลได้เมื่อแหล่งข้อมูลรองรับ
- ซ่อนคำแปลเมื่อไม่มีข้อมูล

คำแปลต้องสัมพันธ์กับบรรทัดที่กำลังแสดง และไม่ควรนำคำแปลของบรรทัดอื่นมาแทนโดยอัตโนมัติ

## 7.3 Multilingual Support

รองรับการแสดงผล Unicode อย่างถูกต้อง รวมถึง:
- Thai
- English
- Korean
- Japanese
- Chinese
- Latin characters with accents
- RTL scripts เมื่อมีการนำมาใช้

ต้องทดสอบการตัดบรรทัด การจัดกึ่งกลาง การแสดงเครื่องหมายวรรคตอน และฟอนต์สำรอง

## 7.4 Lyrics Source Matching

เมื่อต้องค้นหาเนื้อเพลง ให้ใช้ข้อมูลที่หาได้ เช่น ชื่อเพลง ศิลปิน ความยาว และเวอร์ชัน เพื่อป้องกันการจับคู่ผิด

ต้องระวังความแตกต่างระหว่าง:
- Official Audio
- Music Video
- Live Version
- Remix
- Acoustic Version
- Lyric Video
- Cover Version

หากไม่มั่นใจว่าตรงกับเพลงใด ควรให้ผู้ใช้เลือกหรือค้นหาใหม่ แทนการแสดงเนื้อเพลงผิดโดยเงียบ ๆ

## 7.5 Manual Lyrics Correction

ควรมีตัวเลือกให้ผู้ใช้:
- ค้นหาเนื้อเพลงใหม่
- เลือกผลการค้นหาอื่น
- ปรับ Offset
- โหลดเนื้อเพลงใหม่
- เปิดเนื้อเพลงแบบไม่ซิงก์เมื่อไม่มี Timestamp

การแก้ไขเนื้อเพลงเฉพาะเครื่องอาจเป็นฟีเจอร์เสริมในอนาคต ไม่จำเป็นต้องทำระบบแก้ไขเต็มรูปแบบตั้งแต่เวอร์ชันแรก

# 8. INTERACTION DESIGN

## 8.1 Hover Controls

ในสถานะปกติ ให้หน้าต่างแสดงเฉพาะเนื้อเพลง

เมื่อเลื่อนเมาส์ไปเหนือหน้าต่าง อาจแสดงแถบควบคุมขนาดเล็ก เช่น:
- Move
- Lock Position
- Toggle Full Lyrics
- Toggle Translation
- Appearance
- Hide

แถบควบคุมควร Fade in อย่างนุ่มนวล และ Fade out เมื่อไม่มีการใช้งาน

ห้ามแสดงแถบควบคุมค้างไว้โดยไม่จำเป็น

## 8.2 Drag & Lock

- มีพื้นที่สำหรับลากย้ายหน้าต่างที่ชัดเจน
- ป้องกันการลากโดยไม่ตั้งใจขณะอ่านข้อความ
- มี Lock Position
- เมื่อ Lock แล้ว หน้าต่างไม่ขยับจากการลากผิดพลาด
- ปลดล็อกได้จากเมนูหรือ System Tray

## 8.3 Click-through Mode

เมื่อเปิด Click-through:
- เมาส์ต้องส่งผ่านหน้าต่างไปยังโปรแกรมด้านหลัง
- ผู้ใช้สามารถคลิก YouTube หรือโปรแกรมอื่นได้
- หน้าต่างยังแสดงเนื้อเพลงอยู่

ต้องมีวิธีปิด Click-through ที่เข้าถึงได้ง่าย เช่น Hotkey หรือเมนู System Tray

อย่าเปิด Click-through โดยไม่มีทางออกที่ชัดเจน เพราะผู้ใช้อาจคิดว่าแอปค้าง

## 8.4 Keyboard Shortcuts

รองรับการกำหนดคีย์ลัดสำหรับ:
- Show / Hide Lyrics
- Toggle Click-through
- Toggle Lock Position
- Toggle Full Lyrics
- Toggle Translation
- Increase / Decrease Font Size
- Adjust Timing Offset
- Reset Offset

คีย์ลัดต้องตรวจสอบการชนกับคีย์ลัดของโปรแกรมอื่น และผู้ใช้ควรเปลี่ยนคีย์ลัดได้

## 9.1 Hover

เมื่อปรับสี ขนาด ความโปร่งใส หรือเอฟเฟกต์:

## 9.4 Loading Feedback

- ไม่ใช้ Spinner ขนาดใหญ่กลางหน้าจอ

## 9.5 Error Feedback

ข้อผิดพลาดควรสื่อสารสั้น ๆ เช่น:

เสนอทางแก้ที่เหมาะสม เช่น ค้นหาใหม่หรือเลือกเนื้อเพลงด้วยตนเอง

# 13. PERFORMANCE & RESPONSIVENESS

ความลื่นไหลเป็นข้อกำหนดหลัก ไม่ใช่ฟีเจอร์เสริม

- UI ต้องตอบสนองทันทีเมื่อผู้ใช้คลิก
- การโหลดเนื้อเพลงต้องไม่ทำให้หน้าต่างค้าง
- งาน Network ต้องไม่บล็อก UI Thread
- ไม่ค้นหาเนื้อเพลงซ้ำทุกครั้งที่มีการอัปเดตเวลา
- Cache เนื้อเพลงที่ค้นพบแล้วอย่างเหมาะสม
- จำกัดการอัปเดต UI ให้เหมาะกับการเปลี่ยนแปลงจริง
- หยุดงานที่ไม่จำเป็นเมื่อซ่อนหน้าต่าง
- ไม่ใช้ CPU/GPU เกินจำเป็นสำหรับหน้าต่างข้อความ
- ป้องกัน Memory Leak จากการเปลี่ยนเพลงหรือสร้าง Animation ซ้ำ
- เมื่อเชื่อมต่อหลุด แอปต้องไม่พังหรือปิดตัวเองโดยไม่จำเป็น

ควรแยกส่วนการเชื่อมต่อ YouTube, การค้นหาเนื้อเพลง, การซิงก์เวลา และการแสดงผลออกจากกัน เพื่อให้แก้ไขปัญหาได้ง่าย

# 17. ACCEPTANCE CRITERIA

ถือว่า UI/UX ผ่านเกณฑ์เมื่อ:

- เปิดแอปแล้วหน้าต่างเนื้อเพลงไม่รบกวนการทำงานหลัก
- ข้อความไม่กระพริบหรือกระโดดโดยไม่มีเหตุผล
- การเปลี่ยนบรรทัดดูต่อเนื่องและเป็นธรรมชาติ
- ผู้ใช้สามารถย้ายและปรับขนาดหน้าต่างได้ง่าย
- ปรับสีและความโปร่งใสแล้วตัวอักษรยังอ่านได้
- Click-through สามารถเปิดและปิดได้อย่างชัดเจน
- เมื่อหยุดหรือเลื่อนเวลา YouTube เนื้อเพลงตอบสนองตามสถานะจริง
- เมื่อไม่พบเนื้อเพลง แอปไม่แสดงข้อมูลที่ผิดโดยเงียบ ๆ
- เมื่อเปลี่ยนเพลง เนื้อเพลงเก่าจะไม่ค้างหรือปะปนกับเพลงใหม่
- หน้าต่างกลับมาตำแหน่งเดิมได้เมื่อเปิดแอปอีกครั้ง
- ผู้ใช้สามารถซ่อนแอปไว้ใน System Tray ได้
- Animation ไม่ทำให้การเลื่อนข้อความหรือการอ่านเนื้อเพลงช้าลง
- การตั้งค่าหลักมีผลทันทีและไม่ต้องเปิดแอปใหม่

# 18. FINAL PRODUCT DIRECTION

ให้พัฒนาแอปนี้ในฐานะ **Premium Desktop Lyrics Utility**

ลำดับความสำคัญ:

1. แสดงเนื้อเพลงถูกเพลงและซิงก์ได้ถูกต้อง
2. หน้าต่างลอยทำงานได้ดีบน Desktop
3. Animation และการเลื่อนข้อความลื่นไหล
4. UI คลีน สวย และอ่านง่าย
5. ปรับแต่งได้โดยไม่ซับซ้อน
6. ใช้ทรัพยากรอย่างมีประสิทธิภาพ
7. เพิ่มลูกเล่นขั้นสูงเฉพาะเมื่อไม่ลดคุณภาพของฟังก์ชันหลัก

**หลักการสุดท้าย:** อย่าพยายามทำให้แอปดูมีฟีเจอร์เยอะที่สุด แต่ให้ทำให้ฟีเจอร์ที่มีอยู่ใช้งานได้ดี ดูสวย และให้ความรู้สึกว่าทุกอย่างถูกออกแบบมาอย่างตั้งใจ

แอปควรให้ความรู้สึกเหมือนเนื้อเพลงเป็นส่วนหนึ่งของ Desktop ไม่ใช่หน้าต่างโปรแกรมอีกอันที่เปิดทิ้งไว้
